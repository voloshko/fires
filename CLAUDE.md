# fires — Оперативный мониторинг лесных пожаров

Веб-сервис и API: обнаружение активных очагов (NASA FIRMS) и картирование гарей
по Sentinel-2 (dNBR/RBR) для Красноярского края и Сибири, полностью на публичных
данных. Техзадание: [docs/TZ.md](docs/TZ.md) — редакция 2, скорректированная по
фактической доступности источников (протокол проверки в §14).

## Spec-Driven Development

**Код не пишется раньше своей спеки.** Дисциплина перенесена из соседних проектов
(`vector_algebra/sdd-template` — слой спек и прослеживаемости, `liquidator` —
слой доказательств). Гейт fail-closed и запускается в CI.

### Workflow

1. **Спека** — `python3 scripts/spec_tools.py add-spec "Title" --requirement REQ-00N [--depends-on SPEC-x,SPEC-y]`.
   Команда считает следующий номер, создаёт `specs/SPEC-NNN-slug.md` из
   `specs/TEMPLATE.md`, добавляет запись в `traceability.json` со статусом
   `planned` и двигает счётчик в `specs/index.md`. Summary / Acceptance Criteria /
   Verification заполняются руками.
2. **Реализация + тесты** — строго по спеке. Работа, которую спека не разрешает,
   требует новой спеки, а не расширения текущей по ходу дела.
3. **Доказательство** — прогон acceptance-команд пишет receipt в
   `evidence/receipts/<SPEC-ID>/`. Правила — [evidence/README.md](evidence/README.md).
4. **Закрытие** — секция `## Resolution` в файле спеки + флип статуса в файле и
   в `traceability.json` одним изменением. Автоматического распространения нет:
   каждый флип — осознанная правка.
5. **Гейт** — `make gate`.

### Статусы (проверяются enum'ом)

`planned → analysis → active → implemented | partial → verified`;
терминальные в любой момент: `deferred | rejected`.

- `partial` — сделано с честным задокументированным сокращением объёма.
  **Никогда** не эвфемизм для «не доделал»: Resolution обязан назвать, что
  именно вырезано и почему.
- `implemented` — критерии приёмки выполнены, проверено самим исполнителем.
- `verified` — независимо перепроверено; **требует PASS receipt'а на диске**,
  иначе гейт падает.
- `rejected` — исследовано и закрыто; Resolution фиксирует сигнал остановки.
  Отрицательный результат — это поставка, а не неудача.

### Что проверяет `make gate`

1. Каждый файл `specs/SPEC-*.md` имеет запись в `traceability.json`.
2. Нет записей, указывающих на несуществующий файл.
3. Нет висящих `depends_on`.
4. Все статусы — из enum'а.
5. Все `requirement` ссылаются на существующий `requirements/REQ-*.md`.
6. Счётчик в `specs/index.md` не протух.
7. **Каждая спека со статусом `verified` имеет PASS receipt.**
8. **Каждый receipt структурно валиден**: обязательные поля, `spec_id` совпадает
   с именем каталога, `status` из enum'а.

Пункты 7–8 — добавление этого проекта поверх шаблона; их негативные тесты лежат
в `scripts/test_check_traceability_sdd.py` и входят в `make gate`.

### Правила честности

Они не декоративные — предметная область позволяет соврать незаметно. Площадь
гари посчитается всегда, доля ложных срабатываний получится любым числом, а
сверить с землёй нечем.

- **`non_claims` обязателен.** Receipt, не называющий границы своего утверждения,
  не принимается. Для этого проекта типично: «не доказывает площадь против
  наземной истины», «покрывает только протестированный MGRS-тайл», «SYNTHETIC —
  доказывает логику, не доказывает поведение на реальных факелах».
- **Порог не двигают после того, как увидели результат.** FAIL-receipt
  публикуется, а не переписывается.
- **Отсутствие данных ≠ отрицательный ответ.** Нет детекций ≠ нет огня (не было
  ли наблюдения?); нет истории ≠ нет факелов; точка вне слоя ≠ точка не
  сельхозземля. Эти различия закодированы в SPEC-2, SPEC-4, SPEC-5, SPEC-6.
- **Число гектаров без `masked_fraction` не публикуется** — оно неинтерпретируемо
  (REQ-002, SPEC-8).
- Заглушки, `test.skip`, нереализованные ветки — это блокеры, а не доказательства.

### Конвенции

- Requirements — широкие пилляры, их намеренно мало (см.
  [requirements/README.md](requirements/README.md)). Не по одному на фичу.
- Одна спека = один связный кусок работы с проверяемыми критериями.
- Прослеживаемость обязательна: `legacy_untracked_specs` пуст и должен таким
  остаться — это greenfield-репозиторий, амнистии нет.

## Ключевые ограничения предметной области

Полностью — в `docs/TZ.md`; здесь то, что чаще всего забывают:

- `LANDSAT_NRT` в FIRMS — **только США и Канада**, по России данных нет.
- `DAY_RANGE` в FIRMS Area API — максимум **5** суток за запрос.
- Фильтр персистентности требует ≥14 суток истории → БД обязательна с первого дня.
- NBR по Sentinel-2 = **B8A + B12** (оба 20 м, пиксель 0.04 га), не B08.
- Пара сцен «до/после» — **строго один MGRS-тайл**.
- Маска облаков — **SCL**; ассета s2cloudless в Planetary Computer нет.
- Севернее ~66° с ноября по февраль оптики нет вообще → статус `deferred`.
- Sentinel-2 берём из **Planetary Computer** (анонимно), CDSE — резерв (нужен токен).
