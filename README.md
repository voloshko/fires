# fires — оперативный мониторинг лесных пожаров

Веб-сервис и REST API: обнаружение активных очагов и картирование гарей с
оценкой площади в гектарах для **Красноярского края и Сибири**, полностью на
публичных данных — без ведомственных систем, требующих регистрации через ЕСИА.

Регион задаётся конфигурацией, а не кодом: расширение на другой регион — правка
`config/*.toml`.

## Что сервис делает

**Этап 1 — очаги.** Опрашивает NASA FIRMS по четырём источникам (три аппарата
VIIRS + MODIS), нормализует несовместимые шкалы достоверности, отсеивает
персистентные промышленные теплоисточники и сезонные сельхозпалы, собирает
точки в события пожаров с устойчивым идентификатором.

**Этап 2 — гари.** По завершившемуся событию подбирает пару сцен Sentinel-2
«до/после», считает dNBR/RBR, классифицирует тяжесть повреждения по шкале USGS и
выдаёт площадь по классам в гектарах — либо честно сообщает, что посчитать не
может.

**Карта и API.** Два слоя, панель отчёта, экспорт в GeoJSON и CSV, восемь
эндпоинтов.

### Что сервис делает, чтобы не соврать

Предметная область позволяет соврать незаметно: площадь гари посчитается всегда,
доля ложных срабатываний получится любым числом, а сверить с землёй нечем.
Поэтому:

- **Голое число гектаров получить нельзя.** `masked_fraction` (доля области под
  облаками), `thresholds_version` и `status` — обязательные поля схемы ответа.
  Площадь, посчитанная по области, наполовину закрытой облаком, внешне
  неотличима от честной.
- **Каждая площадь проходит перекрёстную проверку.** Считается, во сколько раз
  чаще случайного термоточки события попадают в пиксели, помеченные гарью.
  Ниже порога — статус `unvalidated` с числами проверки, и опубликовать такой
  результат как проверенный невозможно.
- **Отсутствие данных ≠ отрицательный ответ.** Нет детекций ≠ нет огня (а был
  ли пролёт?); нет истории ≠ нет факелов; точка вне слоя ≠ точка не
  сельхозземля; полярная ночь ≠ ноль гектаров.
- **Приостановка называется приостановкой.** Севернее ~66° с ноября по февраль
  оптики нет вообще: событие получает статус `deferred` с причиной и датой
  возврата, а не нулевую площадь.

## Быстрый старт

```bash
git clone <repo> && cd fires
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

### Быстрый старт на готовом кеше

В репозитории лежит кеш снимка за 60 суток — 933 354 детекции, 2562 события и
6 расчётов гари в 14.5 МБ (Parquet со сжатием zstd). Сервер поднимается **за
8 секунд и не требует никаких ключей**:

```bash
make serve          # http://127.0.0.1:8077/
```

Кеш отражает состояние на 18.09.2026 и с возрастом устаревает; `/api/v1/health`
показывает момент сборки, а не текущий.

### Работа на живых данных

Получите бесплатный ключ FIRMS на
https://firms.modaps.eosdis.nasa.gov/api/map_key/ (нужен только email, ключ
приходит письмом) и впишите его в `.env`:

```bash
FIRMS_MAP_KEY='ваш-ключ'
```

Остальные учётные данные необязательны: Sentinel-2, Landsat, MCD64A1 и ESA
WorldCover берутся из Microsoft Planetary Computer **анонимно**. Earthdata
Login понадобится только для многолетнего архива FIRMS (SPEC-10).

Запуск на свежих данных:

```bash
set -a && . ./.env && set +a && python3 -m src.api --config config/krasnoyarsk.toml --days 25 --burns 3 --port 8077
```

Сборка занимает минуты: `--days 25` — это около 20 запросов к FIRMS плюс чтение
сцен Sentinel-2 под каждый расчёт гари; 60 суток собираются около 13 минут.
Пересобрать коммитимый кеш: `make cache`.

## Команды

```bash
python3 -m src.firms fetch --config config/krasnoyarsk.toml --day-range 2
```
Сырые детекции по региону: сколько точек дал каждый источник.

```bash
python3 -m src.masks fetch-worldcover --config config/krasnoyarsk.toml --bbox 87,51,102,57
```
Прогрев кэша сельхозземель. Тайлы 3×3° кладутся локально уменьшёнными; южный
пояс края — 10 тайлов, 888 КБ, около 45 секунд.

```bash
python3 -m src.persistence analyse --config config/krasnoyarsk.toml --days 25
```
Персистентные теплоисточники: собирает историю и показывает, что уходит в
служебный слой.

```bash
python3 -m src.events list --config config/krasnoyarsk.toml --days 25
```
События пожаров: сколько, какие крупнейшие, какие завершены.

```bash
python3 -m src.burn run --config config/krasnoyarsk.toml --days 25
```
Площадь гари для крупнейшего события, с проверкой.

```bash
python3 scripts/validate_burn_controls.py
```
Прогон перекрёстной проверки на контрольных пожарах трёх широтных поясов.

## API

| Метод | Путь | Отдаёт |
|---|---|---|
| GET | `/api/v1/hotspots` | События пожаров, GeoJSON (`bbox`, `date_from`, `date_to`) |
| GET | `/api/v1/hotspots/{id}` | Одно событие с полной историей детекций |
| GET | `/api/v1/burns` | Гари с площадью по классам, GeoJSON |
| GET | `/api/v1/burns/{id}` | Одна гарь: площадь, маска, обогащение, сцены |
| GET | `/api/v1/stats/area` | Агрегат площади по классам |
| GET | `/api/v1/flares` | Служебный слой персистентных теплоисточников |
| GET | `/api/v1/health` | Состояние источников |
| GET | `/` | Веб-карта |

`/api/v1/health` различает **время последнего успешного опроса** и **время
последней полученной детекции**. Это разные величины: опрос может идти успешно и
возвращать пусто неделями, и их смешение скрывает деградацию источника.

## Соревновательный контур: чипы, модели, submission.csv

Отдельный от сервиса тракт под кейс мониторинга пожаров. Вход — чипы двух типов,
выход — один файл `submission.csv`. Два модуля:

| | AF — активное горение | BS — площадь и степень гари |
|---|---|---|
| Чип | 256×256 @ 375 м | 512×512 @ 20 м |
| Вход | VIIRS I1–I5, углы съёмки, `landcover dem t2m rh2m wind` | Sentinel-2 до/после (10 каналов), Sentinel-1, `dem slope landcover` |
| Выход | 1 строка на чип, класс 1 | 3 строки на чип, классы 1–3 |
| Метрика | микро-F1 | IoU гари и mIoU степеней |

**Модуль инференса не имеет доступа к сети по устройству**: он читает только
каталог чипов и модель с диска. Применение готовых продуктов обнаружения
пожаров (FIRMS, VNP14, MOD14) для ответов — основание для снятия с конкурса,
и запрет обеспечен конструкцией, а не обещанием.

### Данные

Архив `fire-train.tar` (2.3 ГБ) распаковывается в `data/comp/train/`:

```bash
tar -xf data/comp/fire-train.tar -C data/comp
```

Получается `train/af/{viirs,aux,masks}/` (420 чипов) и
`train/bs/{sentinel2_pre,sentinel2_post,sentinel1_pre,aux,masks}/` (224 чипа),
в каждом каталоге — свой `meta.csv`.

### Порядок запуска

Порядок не произволен: **пороговый baseline публикуется до обучения**, иначе
сравнение можно построить задним числом.

```bash
python3 scripts/run_baseline.py   # порог USGS по гари → data/comp/baseline_bs.json
python3 scripts/run_train.py      # бустинг по гари    → models/bs_hgb.pkl
python3 scripts/run_af.py         # порог и бустинг по активному горению → models/af_hgb.pkl
```

`run_baseline.py` заодно пишет разбиение `data/comp/split_bs.json` — деление
идёт **по `fire_event_id`, а не по чипам**: соседние фрагменты одного пожара,
попавшие по разные стороны, завышают оценку. В AF-метаданных это поле пусто
целиком, поэтому там деление по чипам, и оценка от этого оптимистична.

### Сборка ответа

```bash
./inference.py --data-dir data/comp/test \
               --out submission.csv \
               --template data/comp/test/sample_submission.csv
```

Без `--model` берётся `models/bs_hgb.pkl`; если файла модели нет, модуль честно
сообщает об этом и падает на пороговый baseline, а не молча выдаёт пустые маски.
С `--template` запускается валидатор и **возвращает ненулевой код при любом
нарушении** формата. Его же можно позвать отдельно:

```bash
python3 -m src.comp.submission validate --file submission.csv \
                                        --template sample_submission.csv
```

Валидатор отвергает лишнюю и недостающую пару `(chip_id, class_id)`,
пересечение классов внутри чипа, выход серии за пределы чипа и пустую ячейку.
Кодирование RLE — пары «начальный пиксель — длина», нумерация **с единицы**,
построчно; смежные серии сливаются в одну (это требование формата, а не
оптимизация).

### Что получилось на своей отложенной части

| Что измеряем | Порог | Модель |
|---|---:|---:|
| Активное горение, F1 | 0.599 | **0.884** |
| Площадь гари, IoU | 0.390 | 0.399 |
| Степень поражения, mIoU | 0.155 | **0.392** |

Перевес по площади гари — 0.008 при 45 чипах отложенной части, то есть в
пределах шума: утверждать превосходство модели по этой метрике нельзя.
Шкала dNBR из учебника выведена для хвойного леса, и в степи она распознаёт
степень поражения втрое хуже обученной модели, хотя контур гари ловит не хуже.
Измерения и то, что они **не** доказывают, — в `evidence/receipts/SPEC-17..19/`.

Все анонимны, кроме FIRMS (бесплатный ключ по email).

| Источник | Что даёт | Доступ |

## Разработка

Проект ведётся по **spec-driven development**: код не пишется раньше своей
спеки, каждое утверждение о качестве подкреплено receipt'ом на диске, а гейт
fail-closed проверяет, что статус `verified` не проставлен без доказательства.
Правила — [CLAUDE.md](CLAUDE.md), спеки — [specs/index.md](specs/index.md).

```bash
make gate          # прослеживаемость + структура receipt'ов + негативные тесты гейта
make spec-status   # авторитетная сводка статусов
python3 -m pytest tests/ -q
```

## Ограничения, которые стоит знать до использования

- **Площадь гари не сверена с наземной истиной.** Перекрёстная проверка по
  термоточкам ловит грубое расхождение, но площадь не измеряет. Сопоставление с
  MCD64A1 и Fire_CCI запланировано (SPEC-11), но не выполнено.
- **Пороги dNBR не валидированы для сибирской растительности.** Шкала USGS
  откалибрована на другой растительности; версия порогов сохраняется вместе с
  каждым результатом именно поэтому.
- **Сервис остаётся пороговым; обучение живёт в соревновательном контуре.** Ни
  одна константа сервиса не подобрана по данным. Модели гари и активного горения
  (SPEC-17..19) работают на чипах кейса и в веб-сервис не встроены.
- **Числа соревновательного контура посчитаны своей отложенной частью и своей
  реализацией метрики**, а не проверяющей системой организаторов; расхождение
  возможно. Оценкой на закрытой выборке они не являются.
- **Снимок данных собирается на старте** и не обновляется, пока сервер работает.
  Оркестрация и автообновление — REQ-005, отдельная работа.
- **Фильтр факелов требует 14 суток истории.** До этого он честно отвечает
  «недостаточно истории», а не «факелов нет».

Всё это записано в receipt'ах в `evidence/receipts/` вместе с тем, что каждое
измерение НЕ доказывает.
