# SPEC-20: Единая команда инференса и воспроизводимость

Status: partial

Requirement: REQ-007

Depends on: SPEC-16, SPEC-17, SPEC-18

## Summary

Требование кейса дословно: решение предоставляет единый способ запуска
инференса, не требующий правки кода.

```sh
python inference.py --data-dir /path/to/test --output /path/to/submission.csv
```

Скрипт принимает каталог с тестовыми чипами в структуре выданного набора,
обрабатывает **все** чипы из `sample_submission.csv`, включая облачные, формирует
файл строго в описанном формате и завершается с кодом 0 без интерактивного
ввода.

Отдельный раздел критериев — скорость работы, 8 баллов, замеряется автоматически
на инфраструктуре организаторов.

**Запрет на сеть здесь не декларация, а свойство.** Правила запрещают получать
ответы по тестовым чипам из FIRMS, MCD64A1 и подобных продуктов. Самый надёжный
способ это гарантировать — сделать инференс физически неспособным выйти в сеть,
а не пообещать, что он этого не делает.

## Acceptance Criteria

- `inference.py` отрабатывает на каталоге тестовых чипов и возвращает код 0;
  выходной файл проходит валидатор SPEC-16. Интерактивного ввода нет.
- **Обрабатываются все чипы шаблона, включая облачные.** Чип, который модель не
  смогла обработать, получает пустую маску, а не пропуск строки: пропуск делает
  файл невалидным целиком.
- Инференс не обращается к сети: тест запускает его с запретом на сетевые вызовы
  и убеждается, что он проходит.
- Зависимости зафиксированы с версиями; случайные начальные значения
  зафиксированы. **Повторный запуск на тех же данных даёт метрику, отличающуюся
  не более чем на 0.005.**
- Замерено и опубликовано время инференса на полном тестовом наборе и требования
  к памяти.
- README содержит: описание решения и схему конвейера, требования к окружению и
  команды установки, ожидаемую структуру входных данных, команду запуска
  инференса с примером и указанием, где появляется `submission.csv`, команду
  запуска обучения, порядок получения и размещения весов, инструкцию по запуску
  сервиса.
- Поставка через Dockerfile либо однозначная инструкция в README — по требованию
  кейса предпочтителен Docker.
