# SPEC-12: Обучающая выборка пар сцен Sentinel-2 с замороженным разбиением

Status: planned

Requirement: REQ-006

Depends on: SPEC-10, SPEC-11

## Summary

Собрать датасет для обучения сегментации гарей: для каждого исторического
события (SPEC-10) — пара сцен Sentinel-2 «до/после», удовлетворяющая
фенологическому ограничению SPEC-9, и маска гари из слабых меток (SPEC-11),
нарезанные на патчи.

**Главный риск этой спеки — утечка между обучением и проверкой, а не объём
данных.** Соседние патчи одного пожара почти идентичны; если они разойдутся по
разные стороны границы разбиения, метрики окажутся завышены, и выигрыш над
baseline будет измерен неверно. Поэтому разбиение выполняется **по событиям и по
годам, а не по патчам**, и фиксируется до начала обучения.

**Ожидание и сигнал остановки.** Ожидается несколько тысяч патчей с обеих
масок. Если после фильтрации по фенологии, облачности и покрытию останется
меньше нескольких сотен патчей на отложенную часть, измерить выигрыш будет
статистически нечем, и SPEC-13 закрывается `rejected` с этим числом.

Каналы: те же B8A и B12, что в SPEC-7, плюс сырые каналы для возможного
расширения. Слабые метки берутся от обоих продуктов раздельно — модель,
обученная на MCD64A1, унаследует его недооценку малых пожаров, и это должно
остаться различимым в SPEC-13.

## Acceptance Criteria

- Разбиение обучение/валидация/отложенная часть выполняется **по событиям**:
  все патчи одного события лежат в одной части. Тест строит датасет из
  событий с пересекающимися патчами и проверяет, что ни один идентификатор
  события не встречается в двух частях.
- Разбиение дополнительно разнесено **по годам**: отложенная часть содержит
  сезоны, отсутствующие в обучении. Межгодовая изменчивость — то, что модель
  обязана переносить, и проверка на том же сезоне её не измеряет.
- Разбиение **записывается на диск и не пересчитывается**: повторный запуск
  сборки с тем же seed и той же версией входных данных даёт побитно тот же
  манифест. Тест сравнивает два прогона.
- Патч с долей валидных пикселей ниже порога отбрасывается на этапе сборки, а
  не маскируется при обучении: причины отбраковки публикуются со счётчиками.
- Каждый патч несёт: идентификатор события, даты обеих сцен, MGRS-тайл,
  разрыв по дню года, продукт-источник метки и долю под маской. Патч без
  любого из этих полей невозможен по схеме.
- Опубликован состав выборки: число патчей по частям, по годам, по широтным
  поясам и по продукту меток.
