# SPEC-36: Изолированный стенд проверки гипотез и честной оценки

Status: active

Requirement: REQ-007

Depends on: SPEC-19

## Summary

Общий экспериментальный контракт для SPEC-27/32..35 в отдельном worktree и отдельном удалённом каталоге. Исторические 35 tune чипов используются только для скрининга. Порог .005 не является проверкой статистической значимости. Успешный скрининг подтверждается внешними фолдами по событиям при наличии пригодных метаданных; настройка выполняется внутри fit каждого фолда.

## Acceptance Criteria

- Отдельный удалённый каталог, доступ к существующему train только через ссылку; собственные models/logs/results. Чужие сервисы не останавливаются, baseline веса не перезаписываются.
- GPU очередь ждёт завершения существующих train очередей и свободной памяти; одна собственная GPU-задача одновременно. CPU ограничен 4 потоками, systemd MemoryMax/CPUQuota, полные логи и коды выхода.
- Каждое предсказание без утечки: проверяемые списки fit/calibration/evaluation, отсутствие пересечений; нормализация только fit. Исторические holdout не используются автоматически.
- Для BS confusion суммируется по пикселям, публикуются IoU_burn, mIoU_sev, W, чистое небо отдельно. AF — pooled F1. Отчёты не смешивают макро и микро.
- Для AF-сети SPEC-27 используется та же вложенная схема, что SPEC-33, чтобы сравнение сети/бустинга было честным; финальная сеть и сабмит только после подтверждения.
- Тесты проверяют разбиения, уникальность mining выборки, метрические крайние случаи, raw входы, сохранение/загрузку и отсутствие доступа к test.
- Повторимый manifest содержит git revision плюс sha256 изменённых файлов, CLI/env, software versions и хеши входных файлов. Receipt не перезаписывается.
- Положительный BS кандидат: 5 фолдов development, группы по событию, фиксированные настройки; независимость групп проверяется. Невозможность группировки явно ограничивает вывод. Для отбора — .005 W и положительная нижняя граница парного bootstrap по группам; test организаторов остаётся неизвестен.

## Frozen pilot configuration

До результатов зафиксировано: BS 200 эпох, batch 8, depth 7, width 32, без JITTER, два сида 20260918/20260919, TTA четыре отражения; AF 100 эпох, batch 8, depth 5, width 16, CE веса [1,200] + Dice, без TTA. Для AF все смеси 0.3..0.7 и пороги выбираются только calibration. Smoke-прогоны на CPU помечаются smoke и не принимаются за измерение качества.

Сетка AF-сети (до первого GPU-замера качества) дополняет HGB GRID точками .01/.02/.05/.1/.2/.3/.4: шкала вероятностей сети может отличаться от HGB. Для парного HGB-контроля и смесей применяется та же расширенная сетка, выбор только внутри calibration. Это не меняет уже выполненный SPEC-33 и его receipt/пороги. Сетка пишется в manifest и summary.

## Confirmation split frozen before GPU outcomes

35 исторических настроечных чипов не входят в оценку подтверждения. Для прошедшего скрининг BS кандидата внешние 5 фолдов формируются по fire_event_id из исходных 144 fit чипов; остальные события + 35 selection чипов обучают модель. Таким образом метрики подтверждения считаются на 144 чипах, которые не использовались для выбора кандидата по IoU. Настройки и число эпох фиксированы заранее; каждое сравнение с контрольной архитектурой использует одинаковые fit/evaluation и заново обученный бустинг. Это всё ещё development-перепроверка, не независимое подтверждение значимости: метки 144 чипов уже косвенно влияли на выбор через обучение исходных кандидатов. Bootstrap после отбора нескольких кандидатов не учитывает весь адаптивный поиск. Это не закрытый тест организаторов. Отсутствующий/пересекающийся event ID блокирует подтверждение.

## Frozen Siamese development revalidation

После положительного двухсидового BF16 скрининга (+.009359 в среднем)
проверяются пять event-фолдов из 144 development-чипов; 35 selection-чипов
всегда только fit. В каждом фолде одинаковые fit/evaluation, один общий
заново обученный HGB и пара optical-BF16 / Siam-BF16. Используются новые
сиды 20260920+k, k=0..4, не выбирается удачный скрининговый сид.
200 эпох, width32 depth7 batch8, все правила постобработки прежние.
Критерий: pooled W delta >=.005 и нижняя граница парного bootstrap по
event IDs >0. Это development revalidation с оговоркой об адаптивном
выборе архитектуры, а не нетронутый тест и не сравнение с чужим датасетом.
