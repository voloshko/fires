# SPEC-13: Дообучение сегментации гарей и сравнение с пороговым baseline

Status: planned

Requirement: REQ-006

Depends on: SPEC-12

## Summary

Обучить модель сегментации гарей на выборке SPEC-12 и измерить, даёт ли она
выигрыш над пороговым dNBR из SPEC-7 на замороженной отложенной части.

**Почему именно сегментация гарей, а не детектирование активного огня.** Этап 2
не привязан к NRT-латентности: гарь картируется по завершении пожара, и повтор
съёмки Sentinel-2 в 5 суток здесь не мешает. Дообучение `pereira-gha/activefire`
на детектирование огня — отдельный, исследовательский трек: продукт работает по
Landsat, повтор съёмки 8–16 суток несовместим с трёхчасовым циклом сервиса, и
даже успешная модель не улучшит оперативную карту (`docs/TZ.md` §7). Методология
Pereira и Sen2Fire при этом применима как точка старта для архитектуры.

**Ожидание и сигнал остановки, сформулированные ДО прогона.** Baseline —
пороговый dNBR с `usgs-baseline-1`. Ожидается выигрыш прежде всего на слабых
классах тяжести, где пороги USGS не откалиброваны под сибирскую растительность.
**Если модель не превосходит baseline по F1 на отложенной части, спека
закрывается `rejected`**, receipt со статусом FAIL остаётся на диске, а
отрицательный результат публикуется как измерение потолка слабых меток.

Модель, даже победившая, **не подключается к сервису этой спекой**: интеграция
в оперативный контур — отдельная работа (REQ-002), и она потребует прохождения
перекрёстной проверки SPEC-9 на общих основаниях.

## Acceptance Criteria

- Baseline воспроизведён на той же отложенной части: пороговый dNBR SPEC-7
  прогоняется по тем же патчам, и его метрики опубликованы **до** обучения
  модели. Порядок обязателен: baseline, посчитанный после, можно подогнать.
- Метрики (precision, recall, F1, IoU) считаются против **обоих** продуктов
  слабых меток раздельно. Результат, приведённый только против одного, не
  принимается.
- Отложенная часть используется **ровно один раз** за прогон; выбор
  гиперпараметров идёт по валидационной части. Receipt фиксирует число
  обращений к отложенной части.
- Пороги и гиперпараметры, зафиксированные до прогона, не меняются после
  просмотра результатов. Изменение любого из них открывает новый прогон с новым
  receipt'ом и новым `run_id`, а предыдущий остаётся на диске.
- Прогон воспроизводим: seed, версия датасета, гиперпараметры и команда
  записаны в receipt; повторный запуск даёт метрики в пределах заявленного
  разброса.
- Модель сравнивается с baseline **и по классам тяжести раздельно**: выигрыш
  в среднем при проигрыше на сильных классах — это не улучшение для задачи
  оценки ущерба.

## Verification

```sh
python3 -m pytest tests/test_training.py -v
python3 -m src.train baseline --dataset data/train --split holdout
python3 -m src.train run --dataset data/train --config config/model.toml
make gate
```

измерены против обоих продуктов меток и опубликованы по классам тяжести.
FAIL здесь — допустимый исход: спека закрывается `rejected` с опубликованным
receipt'ом.

Receipt: `evidence/receipts/SPEC-13/`, класс `REPLAY` (датасет заморожен), с
seed, гиперпараметрами, числом обращений к отложенной части и метриками по
обоим продуктам меток.

`non_claims` обязан включать: метрики измерены против слабых меток, а не против
наземной истины, и потолок качества ограничен качеством этих меток; выигрыш на
отложенной части Красноярского края не переносится на другие регионы без
повторного измерения; модель не подключена к сервису и её пригодность для
оперативного контура этой спекой не доказана.
