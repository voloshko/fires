# SPEC-1: Конфигурация региона и приём FIRMS Area API

Status: implemented

Requirement: REQ-001

Depends on: —

## Summary

Регион задаётся конфигурацией (bbox, имя, часовой пояс), а не константой в коде —
без этого расширение на Сибирь, заявленное в ТЗ §1, требует правки кода. Модуль
опрашивает FIRMS Area API по четырём источникам (`MODIS_NRT`, `VIIRS_SNPP_NRT`,
`VIIRS_NOAA20_NRT`, `VIIRS_NOAA21_NRT`), разбирает CSV и отдаёт нормализованные
детекции.

Два ограничения источника, проверенные 18.09.2026 и зафиксированные в
`docs/TZ.md` §3.1, определяют дизайн: `DAY_RANGE` не может превышать **5**
(в исходном исследовании ошибочно указывалось 10), а `LANDSAT_NRT` покрывает
только США и Канаду и по России данных не даёт — источник исключён, обращаться к
нему нельзя даже «на всякий случай».

«Done»: по команде из CLI модуль забирает детекции по bbox Красноярского края за
последние 2 суток из всех четырёх источников и печатает их число по каждому, не
падая при пустом ответе и при недоступности одного из источников.

## Acceptance Criteria

- Регион читается из конфигурационного файла; смена bbox на любой другой регион
  Сибири не требует изменений в `.py`-файлах. Тест подаёт два разных bbox и
  проверяет, что сформированные URL различаются соответствующим образом.
- `DAY_RANGE > 5` отклоняется на этапе валидации параметров с внятной ошибкой,
  а не отправляется в API. Тест: `day_range=6` возбуждает исключение.
- `LANDSAT_NRT` отсутствует в списке допустимых источников; попытка его
  запросить — ошибка конфигурации. Тест проверяет отказ по имени источника.
- Парсер CSV корректно обрабатывает три случая: непустой ответ, пустой ответ
  (только заголовок) и ответ с сообщением об ошибке от FIRMS вместо CSV. Тест
  покрывает все три на зафиксированных фикстурах.
- Отказ одного источника не прерывает опрос остальных: результат содержит данные
  доступных источников и явный список сбойных.
- `FIRMS_MAP_KEY` читается только из окружения. Grep по репозиторию не находит
  значения ключа ни в одном файле.

## Verification

```sh
python3 -m pytest tests/test_firms.py -v          # офлайн, на фикстурах
python3 -m src.firms fetch --config config/krasnoyarsk.toml --day-range 2

```

PASS: все тесты зелёные; CLI печатает ненулевое число детекций хотя бы по одному
VIIRS-источнику; в выводе нет `LANDSAT_NRT`.

Receipt: `evidence/receipts/SPEC-1/` — класс `REPLAY` для тестов на фикстурах и
класс `LIVE` для прогона CLI (с указанием UTC-окна запроса, поскольку живой ответ
FIRMS невоспроизводим задним числом).

`non_claims` обязан включать: не доказывает корректность самих детекций NASA, не
доказывает полноту покрытия региона, не доказывает поведение при исчерпании квоты.

## Resolution

Status: **partial** — критерии приёмки выполнены, но живая проверка из секции
Verification не выполнена. Причина названа ниже; это не «почти доделано», а
конкретный недостающий артефакт.

### Что сделано

| Файл | Назначение |
|---|---|
| `config/krasnoyarsk.toml` | регион и параметры опроса |
| `src/firms.py` | загрузка конфига, валидация, сборка URL, парсер CSV, опрос, CLI |
| `tests/test_firms.py` | 29 тестов, по одному-нескольким на каждый критерий |
| `tests/fixtures/*` | четыре зафиксированных ответа FIRMS |

Измеренный результат: **28 passed, 1 skipped**.

### Планировалось против найденного

- **Схемы CSV расходятся сильнее, чем предполагала спека.** Заложено было только
  различие имени канала яркостной температуры (`brightness` у MODIS против
  `bright_ti4` у VIIRS). Обнаружилось второе: `confidence` у MODIS — число 0–100,
  у VIIRS — буква `l`/`n`/`h`. Приводить их здесь я не стал: это предмет SPEC-3,
  и приведение в двух местах разошлось бы. Поле сохраняется сырым, тест
  `test_ac04_parses_nonempty_modis_csv_with_different_brightness_column`
  фиксирует `confidence == "78"` как ожидаемое поведение.
- **Добавлено требование, которого в спеке не было: `redact()`.** AC-06 требовал
  только чтения ключа из окружения. При реализации выяснилось, что ключ
  подставляется прямо в URL, а URL попадает в текст исключений httpx — то есть
  в логи и, что хуже, в receipt'ы. Утечка была бы незаметной. Добавлены функция
  `redact()` и два теста (`test_ac06_redact_removes_the_key_from_any_text`,
  `test_ac06_failure_messages_do_not_leak_the_key`). Это расширение объёма
  относительно текста спеки, и оно здесь названо, а не протащено молча.
- **Валидация bbox добавлена сверх спеки.** AC-01 требовал только читаемости
  конфига. Перепутанный порядок координат (`east < west`) — ошибка, которая иначе
  дала бы пустой ответ FIRMS, неотличимый от «пожаров нет». Отбивается в
  `load_region`.
- **Различие «все источники упали» и «источники ответили пусто».** В спеке
  не оговорено. CLI возвращает код 1 только если упали все источники; пустой
  результат — это код 0, потому что отсутствие пожаров в окне — нормальный ответ.

### Что сделано НЕ было

- **Живой запрос к FIRMS не выполнялся.** `FIRMS_MAP_KEY` отсутствует в
  окружении. Receipt `SPEC-1-LIVE-001` имеет статус `INSUFFICIENT_EVIDENCE` и
  честно фиксирует, что команда не запускалась. Из-за этого нет доказательства,
  что реальная схема CSV совпадает с фикстурами, написанными по документации.
- **Grep-проверка AC-06 пропущена** (`SKIPPED`) — без ключа искать нечего.
- Ретраи, backoff и учёт квоты MAP_KEY не реализованы: это REQ-005, отдельная
  работа, и здесь их отсутствие не маскируется.

### Что переводит спеку в `implemented`

Получить бесплатный ключ на https://firms.modaps.eosdis.nasa.gov/api/map_key,
положить в `FIRMS_MAP_KEY` и выполнить:

```sh
python3 -m src.firms fetch --config config/krasnoyarsk.toml --day-range 2
python3 -m pytest tests/test_firms.py -q     # grep-тест перестанет пропускаться
```

Результат оформляется receipt'ом-преемником с `predecessor_run_id`
= `SPEC-1-LIVE-001`. Если живая схема CSV разойдётся с фикстурами — это
находка, а не сбой: фикстуры правятся, расхождение фиксируется здесь.

`.gitignore`, а не хардкодится, поэтому останется верным после `git init` и при
изменении `.gitignore`. Формулировка AC-06 выше сохранена как есть — правка
задним числом скрыла бы, что критерий был сформулирован неточно.
