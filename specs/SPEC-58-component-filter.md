# SPEC-58: Фильтр компонент бледной гари: принять или отбросить пятно, которое видит только бустинг

Status: rejected

Requirement: REQ-007

Depends on: SPEC-42, SPEC-47

## Summary

Бледные гари: 12 из 144 пожаров потеряны целиком и в v22. Бустинг с SWIR их
видит (0.8–1.0 на истине), но по пикселю (SPEC-42, τ и N) и по чипу целиком он
заливает ложной площадью. Ресёч №3 (блок B): не пройден **уровень компоненты** —
второй классификатор принимает или отбрасывает связное пятно, которое видит
только бустинг, по признакам пятна; при n ≈ 12–14 положительных — только
ручные признаки, ≤ 3–5, регуляризованная логистика, leave-one-fold-out; ключевой
новый признак — контраст по Red/Red-edge (dNDVI, dNDRE), потому что SWIR-индексы
не отделяют гарь от скошенного поля (M ≈ 1.0), а Red/Red-edge отделяют (M ≈ 2.7).

Реализация: `scripts/exp_component_filter.py`. Рецепт — v22-аналог на фолдах
(оптика соседа, сиам с радаром, бустинг SWIR). Кандидаты — компоненты бустинга
≥ 20 пикс. без пересечения с выходом рецепта. Признаки: log площади,
компактность, контраст dMIRBI к кольцу 5 пикс., контраст dNDVI, контраст dNDRE,
средние p гари бустинга и сиама. **Предзаявленные наборы**: A = (dMIRBI, dNDVI,
log площадь); B = A + dNDRE; C = B + p бустинга + p сиама. Метка компоненты —
доля истинной гари > 0.5. Печатаются оракул (все истинные компоненты) и «принять
все» (аналог SPEC-42) как потолок и пол.

**Критерий**: пул фолдов выше рецепта на ≥ 0.003 **и** потерянных меньше **и**
35 чипов не ниже — для одного из наборов A/B/C, причём выбор набора — по фолдам,
35 чипов только проверка. Сигнал остановки: оракул сам ниже +0.005 (ловить
нечего) или ни один набор не проходит. Не делается: обучаемые признаки
компонент (n мало), правила по одному порогу (это SPEC-42).

**Ступень 2 (дописана после провала ступени 1, до её запуска).** Ступень 1 с
`class_weight='balanced'` и порогом 0.5 принимает почти всё (−0.10 на фолдах при
оракуле +0.031): ошибка рабочей точки, не признаков. Ступень 2: логистика без
балансировки; порог принятия τ ∈ {0.50…0.95} выбирается по пулу **фолдов 0–2**,
затем применяется к **фолдам 3–4** и к 35 чипам. Критерий тот же (пул 5 фолдов
≥ +0.003, потерянных меньше, 35 чипов не ниже) плюс проверочные фолды 3–4 не
ниже нуля. Печатается AUC признаков по LOFO — мера того, несёт ли Red/Red-edge
контраст сигнал независимо от рабочей точки.

## Acceptance Criteria

- `exp_component_filter.py` печатает число компонент и истинных, оракул, «принять все», три набора на фолдах (LOFO) и 35 чипах, потерянные.
- Принято → фильтр в `postproc`/`inference.py` (признаки без меток), v23.

## Verification

- На k8plus: `CUDA_VISIBLE_DEVICES= OMP_NUM_THREADS=6 .venv/bin/python scripts/exp_component_filter.py`.

## Resolution

**Отклонено по предзаявленным критериям — обе ступени.** `exp_component_filter.py`,
рецепт v22-аналог на 144 групповых чипах; кандидаты — 3937 компонент бустинга без
пересечения с выходом, из них истинных (доля истины > 0.5) 497, медиана 56 пикс.

| | фолды, взвешенно | потеряно | 35 чипов |
|---|---|---|---|
| рецепт | 0.7335 | 12 | 0.7673 |
| **оракул** — принять все истинные компоненты | **0.7647 (+0.0312)** | **6** | +0.0108 |
| принять все компоненты (аналог SPEC-42) | 0.6198 (−0.114) | 17 | −0.165 |
| ступень 1: логистика, balanced, τ = 0.5, наборы A / B / C | −0.105 / −0.103 / −0.053 | 16 / 16 / 13 | −0.165 / −0.159 / −0.104 |
| ступень 2, A (dMIRBI, dNDVI, площадь), AUC 0.499 | τ = 0.50: 0 | 12 | 0 |
| ступень 2, B (+ dNDRE), AUC 0.515 | τ = 0.80: 0 | 12 | 0 |
| ступень 2, C (+ p бустинга, p сиама), AUC 0.590 | τ = 0.65: выбор +0.0025, проверка 0, пул **+0.0016** | 11 | 0 |

Ступень 1 — ошибка рабочей точки (balanced-веса принимают семь ложных на одну
истинную). Ступень 2 честно показывает главное: **признаки не разделяют.**
Медианы истинные | ложные: dMIRBI-контраст 0.106 | 0.079 (AUC 0.555), dNDVI
0.019 | 0.018 (0.511), dNDRE 0.010 | 0.008 (0.525), площадь (0.555), p бустинга
0.786 | 0.784 (0.514). Единственный признак с сигналом — **p сиама** 0.036 | 0.002
(AUC 0.714): бледное пятно истинно, если сиам его хотя бы едва заметил. Гипотеза
ресёча №3 о Red/Red-edge контрасте на уровне компоненты на наших данных не
подтверждается: гарь и её ложные двойники (скошенное поле, сенесценция) в
степи по dNDVI/dNDRE не различаются.

Резерв реален и огромен (+0.031, вдвое больше всего пути v16 → v22), но ключ к
нему — не спектр компоненты. Направление для следующего брифа: почему сиам
«едва видит» истинные бледные пятна (p 0.036) и можно ли усилить именно этот
слабый сигнал, не трогая остальное; и что в ложных пятнах бустинга (7 из 8)
общего — вероятно, они и есть та ложная площадь SWIR на скошенных полях.

Не делалось: обучаемые признаки компонент, текстура GLCM внутри компоненты,
признаки истории (нет второй даты «до»). Код продукта не менялся.
