# SPEC-69: Обогнать Prithvi на лесе: наш U-Net на HLS Burn Scars

Status: partial

Requirement: REQ-008

Depends on: SPEC-66

## Summary

SPEC-66 дал наш U-Net (w32, глубина 7, 6 полос, 60 эпох, отражения при обучении,
4 отражения при инференсе) 0.8386 IoU гари на HLS Burn Scars validation 264.
Prithvi-EO-2.0-300M BurnScars одной меркой — **0.8622** (разовый замер
2026-09-22, вероятности `research/prithvi-hls-val-v1/probabilities.npy`).
Цель — обогнать его своей моделью без чужих весов.

**Протокол (записан до обучения, не меняется):**

1. **Validation 264 не участвует в выборе.** Подбор рецепта — на отложенной части
   training: 20 % тайлов MGRS по хешу `hls-hold:{tile}` (сцены одного тайла целиком
   по одну сторону), остальное — подгонка.
2. **Ступень 1 — выбор рецепта** (один сид, `--fit inner`), кандидаты:
   - C0 — рецепт SPEC-66 (контроль);
   - C1 — плюс повороты на 90°, случайное усиление каналов ×[0.9, 1.1], 120 эпох;
   - C2 — C1 с шириной 48, 100 эпох.
   Все меряются с 8 преобразованиями при инференсе (отражения × повороты). Победитель —
   наибольший IoU гари на отложенной части; при разнице с C0 меньше 0.003 берётся C0
   (не подгоняем шум). Там же выбирается порог из сетки 0.30–0.70 шагом 0.05.
3. **Ступень 2 — финал**: победитель на всех 540 сценах, **5 сидов**, среднее
   вероятностей, выбранный порог. Validation трогается **один раз**.
4. **Критерий**, IoU гари по пулу пикселей validation:
   - **обогнали** (`implemented`): IoU > 0.8622 **и** нижняя граница 95 %
     бутстрепа по сценам (1000 выборок) разницы «наш − Prithvi» > 0;
   - **догнали** (`partial`): IoU ≥ 0.8622, но интервал включает ноль;
   - иначе `rejected`, разрыв записывается.
   Вторичные числа (не решают): mIoU двух классов, IoU гари в среднем по сценам,
   одиночный сид против ансамбля.

**Оговорки заранее**: чекпойнт Prithvi, вероятно, выбирали по той же validation —
их 0.8622 может быть завышено, и это в пользу Prithvi, а не нас. Обгон на 264
сценах HLS (США, 30 м) не доказывает ничего про Сибирь.

Стоимость: 3 прогона ступени 1 + 5 финальных ≈ 4–7 ч GPU параллельно с очередью SPEC-67.

## Resolution

**Догнали, не обогнали.** Receipt `evidence/receipts/SPEC-69/SPEC-69-HLS-001.json` (INSUFFICIENT_EVIDENCE).

Ступень 1, 113 отложенных сцен (тайлы целиком): C0 0.741, **C1 0.806**, C2 0.794 →
C1, порог 0.7 (край сетки 0.30–0.70).

Ступень 2, validation 264, IoU гари по пулу:

| модель | IoU гари | mIoU | по сценам |
|---|---|---|---|
| Prithvi-EO-2.0 (0.5) | 0.8622 | 0.9233 | 0.8107 |
| наш SPEC-66 | 0.8386 | 0.9104 | 0.7939 |
| C1, одиночные сиды | 0.855–0.872 | 0.920–0.929 | 0.816–0.826 |
| **C1, ансамбль 5** | **0.8666** | 0.9262 | 0.8251 |

Разница с Prithvi +0.0044, 95 % [−0.024, +0.029] — интервал включает ноль,
поэтому `partial` по заранее записанному критерию.

Что вырезано из «обогнали» и почему: бутстреп не отделяет нас от Prithvi —
разброс сидов (0.855–0.872) шире самой разницы.

Задним числом, не решает: при пороге 0.5 ансамбль даёт 0.8704 (выше и Prithvi
с 8 преобразованиями, 0.8684). Порог 0.7 выбран по правилу на отложенных тайлах;
заявить 0.8704 нельзя — validation уже использована, и любой новый порог,
выбранный на ней, будет подгонкой. Честная проверка — только на данных, которых
ни одна из моделей не видела.

Отклонение от протокола: C2 упал с нехваткой памяти в первую ночь (гонка при старте
рядом с SPEC-67) и был перезапущен без изменений; финальные сиды 3–5 учились по два
одновременно через общий старт `scripts/queues/gpu_run.sh`. На числа не влияет.

Не сделано: ансамбль больше 5 сидов, другие пороги, другие архитектуры — после
касания validation это уже не проверка.
