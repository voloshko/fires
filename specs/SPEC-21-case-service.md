# SPEC-21: Сервис под требования кейса — контуры и три класса

Status: planned

Requirement: REQ-007

Depends on: SPEC-8, SPEC-18

## Summary

Информационно-аналитический сервис — отдельный раздел критериев на 12 баллов,
оценивается экспертами по демонстрации. Существующий сервис (SPEC-8) закрывает
его частично; эта спека доводит его до требований кейса.

Минимальный функционал по постановке и что уже есть:

| Требование кейса | Статус |
|---|---|
| Приём полигона или bbox и интервала дат | есть, параметры запроса |
| Карта термоточек за период | есть |
| **Векторные контуры гарей в GeoJSON или Shapefile** | нет: сейчас отдаются прямоугольники bbox, а не контуры |
| Аналитическая справка: площадь в га и распределение по **трём** степеням | частично: у нас пять классов по шкале USGS |
| REST API для тех же результатов без интерфейса | есть |

Три отличия от текущего состояния:

1. **Векторизация.** Нужны настоящие контуры гари, а не ограничивающие
   прямоугольники событий. Растр классов превращается в полигоны.
2. **Три класса вместо пяти.** Кейс требует слабую, среднюю и сильную степень.
   Наши `unburnt`, `low`, `moderate_low`, `moderate_high`, `high` сводятся к
   трём; правило сведения фиксируется явно, а не выбирается на глаз.
3. **Регион.** Нижнее Поволжье и Подонье вместо Красноярского края — правка
   конфигурации, не кода: параметризация региона доказана в SPEC-1.

Постановка прямо разрешает работать на заранее подготовленном ограниченном
наборе сцен: разворачивать полный конвейер скачивания не требуется. Наш кеш
(SPEC-14) этому соответствует.

## Acceptance Criteria

- Контуры гари отдаются как полигоны в GeoJSON; тест проверяет, что геометрия —
  `Polygon` или `MultiPolygon`, а не прямоугольник bbox события.
- Сведение пяти классов к трём задано таблицей в конфигурации и версионировано;
  суммарная площадь при сведении сохраняется. Тест на синтетике.
- Аналитическая справка выгружается в машиночитаемом виде и содержит суммарную
  площадь в гектарах и распределение по трём степеням.
- Регион меняется правкой конфигурации: тест подаёт конфигурацию Нижнего
  Поволжья и проверяет, что запросы формируются по её bbox.
- Все существующие гарантии SPEC-8 сохраняются: площадь не отдаётся без
  `masked_fraction`, `thresholds_version` и `status`; непроверенный результат
  помечен.
- Сервис запускается командой из README и демонстрируется на подготовленном
  наборе сцен.

## Verification

```sh
python3 -m pytest tests/test_case_service.py -v
python3 -m src.api --config config/povolzhye.toml --cache data/demo --port 8077
curl -s 'http://127.0.0.1:8077/api/v1/burns?bbox=42,47,44,49' | head -c 400
make gate
```

PASS: тесты зелёные; контуры отдаются полигонами, справка содержит три степени,
регион задаётся конфигурацией.

Receipt: `evidence/receipts/SPEC-21/`, класс `REPLAY` для тестов и `LIVE` для
демонстрации с примерами ответов.

`non_claims`: не доказывает, что контуры совпадают с эталонными — это предмет
метрики раздела 0; сведение пяти классов к трём — наше решение, а не
установленное кейсом соответствие.
