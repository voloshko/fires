# SPEC-29: Происхождение разметки BS: аудит остатка ложной гари

Status: implemented

Requirement: REQ-007

Depends on: SPEC-19

## Summary

После фильтра чужих пожаров ложная гарь на 35 настроечных чипах — ~155 тыс.
пикселей, и треть её сидит в трёх чипах: BS_tr_000016 (истина обрезана
прямой линией, не совпадающей ни с одним слоем входа: SCL, aux, S1 — проверено
`exp_stack.py`), BS_tr_000108 (убранные поля), BS_tr_000160 (соседняя гарь,
сросшаяся с главной). Эти ошибки — семантика разметки «один пожар — один
периметр», и модель их не снимет. Единственный способ продвинуться — понять,
**как строилась разметка**, и это законно делать на обучающих чипах: у них
есть привязка и даты, а FIRMS и MCD64A1 для исторических данных ресёрчем кейса
разрешены (запрет — только на ответы по тесту).

Задача спеки — не модель, а **аудит**: для 15 худших по ложной гари обучающих
чипов сопоставить истину с (а) детекциями FIRMS VIIRS в окне
`date_pre…date_post`, (б) MCD64A1 за те месяцы, (в) периметром выпуклой
оболочки детекций, (г) границами Sentinel-2 сцен обеих дат. Ответить на три
вопроса: чем задан обрез прямой линией; входит ли в истину гарь без детекций
FIRMS в окне; совпадает ли граница истины с MCD64A1 или с dNBR-порогом.

**Ожидание:** объяснение найдётся для обреза (граница сцены или тайла
источника разметки) с вероятностью выше половины; правило для соседних гарей —
вряд ли, потому что в тесте нет ни дат, ни привязки, и любое найденное правило
должно выражаться через входы чипа. **Сигнал остановки:** если за два часа
работы ни одно наблюдение не переводится в правило по входам чипа — спека
закрывается `implemented` как аудит с выводами, без изменения модели.

## Acceptance Criteria

- `scripts/audit_labels.py`: для 15 чипов — таблица: fp-площадь, доля fp с
  детекциями FIRMS в окне / без, расстояние от главного пятна, тип покрова,
  совпадение обреза истины с границей сцены (по nodata полос и по геометрии
  тайла). Запросы FIRMS — через уже существующий `src/firms.py`.
- Раздел в `evidence/hypotheses.md` «Происхождение разметки» с ответами на
  три вопроса и явным списком «выражается через входы чипа / не выражается».
- Если найдено правило по входам чипа — оно проверяется честно на половинах,
  как `drop_far` (`scripts/exp_far.py`), и только тогда попадает в
  `src/comp/postproc.py`.
- Ни один запрос к FIRMS/MCD64 не делается для тестовых чипов; `inference.py`
  не меняется, если правило не найдено.

## Verification

- `python scripts/audit_labels.py` печатает таблицу; та же таблица в журнале.
- `grep -n "Происхождение разметки" evidence/hypotheses.md`.
- `git log -p -- inference.py` за период спеки — без изменений, кроме принятого правила с receipt.
- Чего не докажет: устройство разметки закрытой выборки; только правдоподобную гипотезу по обучающей.

## Resolution

**Аудит выполнен полностью, правило не найдено.**
Ответы на три вопроса спеки:
1. *Чем задан обрез прямой линией (BS_tr_000016)?* Не краем полосы Sentinel-2
   (все сцены с одной орбиты 35, nodata 0 %), не границей тайла MODIS, не
   nodata вспомогательных слоёв, не маской SCL. Остаётся неизвестным; по
   `meta.cloud_frac` сцена разметки у этого чипа совпадает с выданной.
2. *Входит ли в истину гарь без детекций?* Да: 30.3 % истинной гари дальше
   1 км от любой детекции VIIRS в окне (1734 детекции на 35 чипов, 95 % из них
   внутри истины). Разметка шире термоточек и не из FIRMS; по MCD64A1 65 %
   истинной гари MODIS не видит. Наша ложная гарь на трёх худших чипах в 0–1 %
   случаев рядом с детекциями — в окне там не горело.
3. *С чем совпадает граница истины?* Не с MCD64A1 (IoU 0.25); `burn_area_ha`
   в meta совпадает с маской точно, `cloud_frac` посчитан по сцене разметки, и
   у ~12 % чипов она отличается от выданной сцены «после» — отсюда истина под
   нашей маской облаков.
Найденное правило (ноль под маской при |meta_cloud − scl_cloud| ≤ 0.05) верно
структурно, но даёт +0.0012 взв. — не внесено. Скрипты
`scripts/audit_labels.py`, `scripts/exp_meta_cloud.py`; записи в
`evidence/hypotheses.md`. FIRMS-часть выполнена с ключом из окружения (`scripts/audit_firms.py`); ключ в репозиторий и логи не попал.
