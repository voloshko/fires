# SPEC-8: REST API и веб-карта

Status: implemented

Requirement: REQ-003

Depends on: SPEC-6, SPEC-7

## Summary

Тонкий слой поверх готовых конвейеров: эндпоинты `/api/v1/hotspots`,
`/api/v1/burns`, `/api/v1/flares`, `/api/v1/health` и карта на Leaflet с двумя
слоями и панелью отчёта. Вся агрегация — на backend.

Ключевое требование, отличающее эту спеку от обычной обвязки: **API не должен
позволять получить голое число гектаров**. Каждый ответ с площадью несёт
`masked_fraction`, `thresholds_version` и `status`. Число гектаров без доли
площади под маской неинтерпретируемо, и возможность его получить — это способ,
которым сервис начнёт врать.

`/api/v1/health` различает время последнего **успешного опроса** и время последней
**полученной детекции**. Их смешение скрывает деградацию источника: опрос может
идти успешно и возвращать пусто неделями.

## Acceptance Criteria

- `/api/v1/burns` и `/api/v1/burns/{event_id}` не могут вернуть `area_ha` без
  `masked_fraction`, `thresholds_version` и `status` — проверяется схемой ответа,
  тест на отсутствие любого из полей падает.
- `/api/v1/health` возвращает по каждому источнику обе величины раздельно; тест
  на состоянии «опросы идут, детекций нет» проверяет, что они различаются.
- `/api/v1/flares` отдаёт служебный слой отфильтрованных персистентных
  источников — без него фильтр SPEC-4 неаудируем.
- События в статусе `deferred` отдаются с причиной и не выглядят как события с
  нулевой площадью. Тест сравнивает два ответа.
- Карта отображает оба слоя и таблицу площади по классам; клик по событию
  открывает карточку. Проверяется вручную, факт проверки фиксируется в receipt'е.
- Секреты не попадают ни в один ответ API: тест грепает сериализованные ответы на
  значение `FIRMS_MAP_KEY` из окружения.

она выполнена человеком, а не автоматикой.

`non_claims`: не доказывает производительность под нагрузкой; не доказывает
корректность самих цифр (это SPEC-6/SPEC-7); ручная проверка карты не является
автоматическим тестом и не защищает от регрессии.

## Resolution

Status: **implemented**. Доказано `SPEC-8-OFFLINE-001` (REPLAY, PASS) и
`SPEC-8-LIVE-001` (LIVE, PASS). **30 passed**, всего по проекту 268.

### Что сделано

`src/api.py` — FastAPI поверх готовых конвейеров, восемь эндпоинтов раздела 9
ТЗ. `static/index.html` — карта на Leaflet: три слоя, панель отчёта по классам
тяжести, карточка события, состояние источников, экспорт в GeoJSON и CSV.

### Главное решение: голое число гектаров получить нельзя

`masked_fraction`, `thresholds_version` и `status` — обязательные поля схемы
pydantic, а не соглашение вызывающего. Тест снимает каждое из них по очереди и
убеждается, что схема отвергает ответ. Площадь, посчитанная по области,
наполовину закрытой облаком, внешне неотличима от честной, и возможность
вернуть её без контекста — это и есть способ, которым такой сервис начинает
врать.

### Площади помечены как непроверенные

SPEC-7 закрыта статусом `partial`: перекрёстная проверка показала, что
вычисленная площадь не выдерживает сопоставления с термоточками
(`SPEC-7-LIVE-002`, FAIL). Поэтому каждый ответ с площадью несёт
`validated: false` и ссылку на причину, а карта показывает предупреждение прямо
рядом с числом гектаров. Отдать 236 957 га молча было бы хуже, чем не отдавать
вовсе. Флаг снимается закрытием SPEC-9, а не правкой этого модуля.

### Два дефекта, найденные проверками

**DEF-01, падение `/health` на живом сервере.** sqlite3 привязывает соединение к
создавшему его потоку, а FastAPI выполняет синхронные обработчики в пуле.
`/api/v1/health` читал журнал наблюдений из рабочего потока и падал с
`ProgrammingError`. Дефект проявился бы и в продакшне, не только в тестах.
Исправлено, потолок задокументирован в коде.

**DEF-02, подложка карты требовала ключ.** Тайлы CARTO стали отдаваться с
надписью «API KEY REQUIRED» — публичный сервис не должен зависеть от чужой
регистрации (REQ-005). Переведено на `tile.openstreetmap.org` без ключа,
затемнение CSS-фильтром. Найдено визуальной проверкой, а не тестом: ни один
юнит-тест такого не увидел бы.

### Проверено на живых данных

888 событий, 57 теплоисточников, 3 расчёта гари (2 успешных, 1 `deferred`).

- **AC-02 на реальных данных:** по всем четырём источникам последний успешный
  опрос 13:01, последние детекции 07:48 / 08:07 / 08:52 / 09:30 — величины
  действительно различаются, и смешение их скрыло бы деградацию источника.
- **AC-04:** `FIRE-3ce352bc7175` отдан со статусом `deferred` и причиной «нет
  пары сцен одного MGRS-тайла с долей валидных пикселей ≥ 80% (кандидатов до:
  66, после: 9)». Карточка `deferred` **не содержит таблицы гектаров** —
  проверено в DOM, а не на глаз.
- **AC-05:** карта открыта во встроенном браузере, клик по очагу открыл карточку
  `FIRE-c744bfd003df`; карточка гари `FIRE-49e34744a400` показала маску 3.3%,
  пороги `usgs-baseline-1`, сцены 2026-07-27 → 2026-09-15 и 91 820 га с
  предупреждением «не проверено».

### Что сделано НЕ было

Снимок данных собирается на старте и не обновляется, пока сервер работает:
`/health` отражает момент сборки. Гари посчитаны для 3 крупнейших событий из
888 — полный пересчёт занял бы часы. Требование НФТ о 2 секундах при холодном
кеше не измерялось: нагрузочного тестирования не было. Всё это — предмет REQ-005
и отдельной работы, а не скрытый долг.
