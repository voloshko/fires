# SPEC-8: REST API и веб-карта

Status: planned

Requirement: REQ-003

Depends on: SPEC-6, SPEC-7

## Summary

Тонкий слой поверх готовых конвейеров: эндпоинты `/api/v1/hotspots`,
`/api/v1/burns`, `/api/v1/flares`, `/api/v1/health` и карта на Leaflet с двумя
слоями и панелью отчёта. Вся агрегация — на backend.

Ключевое требование, отличающее эту спеку от обычной обвязки: **API не должен
позволять получить голое число гектаров**. Каждый ответ с площадью несёт
`masked_fraction`, `thresholds_version` и `status`. Число гектаров без доли
площади под маской неинтерпретируемо, и возможность его получить — это способ,
которым сервис начнёт врать.

`/api/v1/health` различает время последнего **успешного опроса** и время последней
**полученной детекции**. Их смешение скрывает деградацию источника: опрос может
идти успешно и возвращать пусто неделями.

## Acceptance Criteria

- `/api/v1/burns` и `/api/v1/burns/{event_id}` не могут вернуть `area_ha` без
  `masked_fraction`, `thresholds_version` и `status` — проверяется схемой ответа,
  тест на отсутствие любого из полей падает.
- `/api/v1/health` возвращает по каждому источнику обе величины раздельно; тест
  на состоянии «опросы идут, детекций нет» проверяет, что они различаются.
- `/api/v1/flares` отдаёт служебный слой отфильтрованных персистентных
  источников — без него фильтр SPEC-4 неаудируем.
- События в статусе `deferred` отдаются с причиной и не выглядят как события с
  нулевой площадью. Тест сравнивает два ответа.
- Карта отображает оба слоя и таблицу площади по классам; клик по событию
  открывает карточку. Проверяется вручную, факт проверки фиксируется в receipt'е.
- Секреты не попадают ни в один ответ API: тест грепает сериализованные ответы на
  значение `FIRMS_MAP_KEY` из окружения.

## Verification

```sh
python3 -m pytest tests/test_api.py -v
uvicorn src.app:app --port 8000     # ручная проверка карты
make gate
```

PASS: тесты зелёные; карта открывается, оба слоя рисуются, панель отчёта считает
гектары.

Receipt: `evidence/receipts/SPEC-8/`, класс `REPLAY` для тестов API. Ручная
проверка карты фиксируется отдельной записью в `acceptance` с явной пометкой, что
она выполнена человеком, а не автоматикой.

`non_claims`: не доказывает производительность под нагрузкой; не доказывает
корректность самих цифр (это SPEC-6/SPEC-7); ручная проверка карты не является
автоматическим тестом и не защищает от регрессии.
